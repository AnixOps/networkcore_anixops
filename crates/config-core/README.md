# config-core

`config-core` contains the first pure configuration and subscription parsing services for the unified network control kernel.

The crate implements `ConfigurationService` for a minimal TOML document shape with `schema_version`, `profile`, `profiles`, `listeners`, `nodes`, and `routes` fields. It normalizes profiles, inbound listeners, local nodes, and default route sets into `ConfigSnapshot` without reading files, making network requests, starting proxy engines, or depending on platform adapters.

The crate also implements `SubscriptionService` as `CoreSubscriptionService`. It accepts explicit `inline:` subscription sources, parses the same minimal TOML `nodes` and `routes` subset, single `ss://`, `trojan://`, `vless://`, `vmess://`, `hysteria2://`/`hy2://`, and `tuic://` URLs, Clash YAML `proxies` catalog imports, sing-box JSON `outbounds` catalog imports, Surge proxy line catalog imports, Loon proxy line catalog imports, Quantumult X proxy/server line catalog imports, plaintext proxy link lists, and base64 encoded proxy link lists into `SubscriptionDocument`, and normalizes them into `NodeCatalog`. Hysteria2 retains the share-link password, port hopping, supported obfuscation, and TLS metadata; TUIC retains UUID, optional password, congestion control, and TLS metadata. Remote subscription fetching, file loading, authentication, DNS, plugin, duplicate-id, and listener/node graph validation remain out of scope for this crate; secrets are only carried as node metadata for adapter translation and must not be echoed in diagnostics.

`networkcore-linux run-url`, the desktop GUIs and the iOS importer turn the normalized catalog into embedded-engine outbounds; the retained V2Ray-family TLS/REALITY/uTLS/transport fields carry through. Hysteria2 and TUIC URL parser gates are catalog import only as far as MITM goes: their foreground path does not enable HTTP/3 MITM. Parsing does not infer unsupported XHTTP, ECH or multiplex fields. Clash YAML parser gates are catalog import only. sing-box JSON parser gates are catalog import only. Quantumult X proxy/server line parser gates are catalog import only. Surge proxy line parser gates are catalog import only. Loon proxy line parser gates are catalog import only. `networkcore-linux start` consumes normalized local configuration through the runtime and native engine path; persisted subscription catalogs are not yet wired into generic runtime startup.

The `routing` module models first-class rules (`DOMAIN`, `DOMAIN-SUFFIX`, `IP-CIDR`/`IP-CIDR6`, `GEOIP`, `FINAL`) and `select`/`url-test`/`fallback` policy groups. A configuration with top-level `rules` and `[[policy_groups]]` produces `ParsedConfigDocument.routing`. `RoutingModel::decide` is the in-process decision interface for `engine-embedded`; GeoIP, DNS, selection, and health results come from a caller-supplied `RoutingEnvironment`. See `docs/architecture/routing-policy-group-model.md` and the shared snapshot fixture in `testdata/routing-snapshot/`.

Verification for this crate is performed only by GitHub Actions, following the repository CI/CD policy.
